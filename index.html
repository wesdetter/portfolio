What I built

Every location sends sales, delivery, comps, promotions, and voids data as Excel files. Worksheet names change, columns shift, and the files pile up. I replaced the manual cleanup with a pipeline that handles all of that, so a refresh updates every page. Each page closes with a plain-English health update that summarizes the numbers: whether traffic or check is driving sales, which stores to call, and what is dragging results.

The data model

Each subject area has its own fact table, and all of them filter through the same dimensions. That keeps a store, a date, or a same-store flag meaning the same thing on every page.

Reusable DAX

Measures are written once and reused on every page. Here is a simplified version of the pattern for year-over-year and same-store sales.

Total Sales = SUM ( FactSales[NetSales] )

Sales LY =
CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( DimDate[Date] ) )

Sales YoY % = DIVIDE ( [Total Sales] - [Sales LY], [Sales LY] )

Same-Store Sales YoY % =
CALCULATE ( [Sales YoY %], StoreAttributes[SameStoreFlag] = TRUE () )

Where the data led to a decision

While analyzing third-party delivery sales, I found an opportunity to run DoorDash sponsored listings in 40 stores and recommended the campaign to marketing. During the 7-week run, year-over-year sales and transactions both moved up. The prior 7 weeks barely moved.
